=== 06. SYSTEM, JOURNEY, AND DATA MAP ===
Scanner journey: Items or Inventory -> hardware/rear-camera/manual code -> as-entered plus one-leading-zero barcode candidates -> exact/unique local match -> current search results; Enter then dismisses suggestions until editing resumes.
Manual stock journey: Inventory action -> choose location -> enter final quantity -> old/new/difference/allocated preview -> optional confirmation reason -> one idempotent audited adjustment -> totals/FIFO/configured writeback follow existing services.
Route journey: Routes / Live Planner -> select open orders -> either map the selection for one equal-time driver or choose the full driver/zone plan -> POST /api/routes/open-orders/plan with explicit order IDs -> exactly-once assignment/unassigned reasons -> in-app stop overview -> continuous Google Maps URLs -> open/share. Routes / Completed Routes contains only the persisted completed-order workflow.
Data boundaries: Order/customer/address snapshots travel from authenticated Pongo backend to the authenticated frontend. They are not sent to Google by the backend; Google receives addresses only when staff opens or shares a generated URL.
Stock CSV journey: Items -> Import CSV -> Override stock levels -> upload/map columns -> review current/new/variance -> confirm -> one audited stock adjustment -> results/history. Quantity authority is the selected active inventory location; item totals remain derived by the existing location inventory service.
Demo journey: operator creates demo user -> prospect signs in -> auth response identifies mock/read-only scope -> global header shows the Mythodus lockup on every workspace -> protected request session switches to the seeded demo database -> existing pages render fictional items, stock, orders, reports, and routes -> writes/integrations return a safe 403.
Live Woo count journey: Dashboard -> Pongo backend requests one row for each active Woo status -> validates `X-WP-Total` headers -> sums verified totals -> renders the isolated KPI; any upstream failure returns safe 503 and leaves all local Dashboard sections intact.
Picked completion journey: Open Orders -> complete a server-confirmed picked order -> validate active/actionable inventory lines only -> close locally without reducing stock again -> continue through the existing guarded Woo status/stock synchronization path.
